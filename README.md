# Лендинг-шаблон для автосервиса и детейлинга

Реализация спецификации из [`description.md`](description.md).

Концепт: страница выглядит не как «сайт с машинами», а как **заказ-наряд, который
собирается на глазах**. Главное обещание — план работ, срок и вилка цены до записи.

**Стек:** Astro 5 · Tailwind 4 · TypeScript · Preact (острова) · GSAP · Lenis
**Хостинг:** GitHub Pages, деплой через GitHub Actions при push в `main`.

---

## Три слоя шаблона

| Слой              | Что это                                                                | Где лежит                                                       |
| ----------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------- |
| **Core**          | структура, анимация, механики, юр. блоки, сетка, тон, логика CTA       | `src/components`, `src/lib`, `src/styles`, `src/scripts`         |
| **Client config** | город, телефон, адрес, услуги, цены, отзывы, часы, гарантия, реквизиты | `src/config/*`, `src/content/*`                                  |
| **Customisation** | выбор H1, палитра в пределах токенов, набор карточек, коэффициенты     | `src/config/client.ts`, `src/config/pricing.ts`, `@theme` в CSS  |

Правило: **ни город, ни телефон, ни цены, ни гарантия не захардкожены вне конфига.**

## Запуск

```bash
npm install
```

```bash
npm run dev
```

Дев-сервер поднимается на `http://localhost:4321/avtodetail-template/` — путь
включает `base`, потому что проект публикуется по подпути GitHub Pages.

| ----------------- | ------------------------------------------------------------- |

## Подмена под нового клиента (~20 минут)

Порядок ровно такой — файлы идут от самого важного к необязательному.

### 1. `src/config/client.ts` — реквизиты и первый экран

- `brandName`, `brandNameShort`, `tagline`
- `city`, `cityIn` (предложный падеж: «в Казани»), `region`, `address`, `addressNote`
- `phone` (для показа), `phoneHref` (для `tel:`), `waPhone` (**только цифры**, для `wa.me`), `email`
- `workHours` (для людей) и `workHoursSchema` (для schema.org, формат `Mo-Sa 09:00-20:00`)
- `ogrn`, `inn`, `legalName`
- `mapUrl` — ссылка на маршрут в Яндекс/2ГИС, `geo` — координаты для разметки
- **`heroH1Index`** — какой из трёх H1 используется. Ровно один вариант на сборку.
- `proof` — цифры полосы доверия (они же анимируются счётчиками)
- `metrikaId` — номер счётчика Яндекс.Метрики. Пусто → счётчик не подключается вообще.
- `seo.title` / `seo.description`

Ниже в том же файле: `processSteps` (как проходит работа) и `equipment` (оборудование).

### 2. `src/config/services.ts` — карточки услуг

Восемь карточек: `title`, `description`, `fromPrice`, `durationHint` и `visual`
(`lift` | `scanner` | `polisher` | `extractor` — какое фото стоит на карточке, один
кадр на две карточки).

На мобильном секция — горизонтальная лента со snap: восемь карточек столбиком
растягивали экран почти на 3000 px, лентой секция занимает ~810 px. От `sm` — сетка.

### 3. `src/config/pricing.ts` — цены и коэффициенты

- `diagnosticFrom` / `toFrom` / `detailingFrom` — строки прайса и база калькулятора
- `urgentAddon` / `pickupAddon` / `materialsAddon` — допы калькулятора, ₽
- `bodyCoefficients`, `conditionCoefficients` — множители
- `priceRows` — строки блока «Цены и условия»

### 4. `src/config/calculator.ts` — базовые цены и сроки услуг

`basePrice` и `baseMinutes` по каждой услуге. Формула лежит отдельно в `src/lib/calc.ts`
и её трогать не нужно:

```
final_price = base_service_price × body_coef × condition_coef + addon_sum
```

Срок: `baseMinutes`, «Сложное» состояние → ×1.3, «Срочный приём» → ×0.8 к ожиданию.

### 5. `src/config/quiz.ts` — вопросы и результаты

Вопросы, варианты, веса score-стеков и тексты результатов (`quizResults`).
Логика подсчёта — `src/lib/quiz-engine.ts`, ей правки не нужны.

### 6. `src/content/reviews.ts` — отзывы

**Важно для приёмки.** В демо все цитаты помечены `isDemo: true` и выводятся с явной
плашкой «демонстрационная цитата». Для реального клиента:

```ts
{ source: '2GIS', text: '…', author: 'Имя из карточки', isDemo: false, screenshot: 'reviews/1.png' }
```

Выдумывать отзывы от имени реальных людей нельзя — это прямой риск по рекламному
законодательству (см. `description.md`, раздел 7).

### 7. `src/content/faq.ts` — вопросы и ответы

Тексты подставляют данные из `client` (гарантия, адрес, режим), поэтому часть ответов
обновится автоматически.

### 8. Юридические страницы

`src/pages/privacy.astro` и `src/pages/consent.astro` — шаблоны политики и согласия,
подставляют реквизиты из `client`. **Перед публикацией их обязан проверить юрист клиента:**
сроки хранения и перечень обрабатываемых данных зависят от фактических процессов.

### 9. Палитра (опционально)

Токены в `@theme` в `src/styles/global.css`. Правило спецификации: **на одном экране
максимум один яркий акцент**, остальное — бумага, металл, графит.

### 10. Фото

Демо-кадры лежат в `src/assets/photos` и подключены через `astro:assets`
(`<Picture>`: AVIF + WebP-фолбэк, lazy, явные размеры):

| Файл                 | Где стоит                    | Компонент              |
| -------------------- | ---------------------------- | ---------------------- |
| `svc-scanner.webp`   | диагностика                  | `ServicePhoto.astro`   |
| `svc-service.webp`   | ТО и расходники              | `ServicePhoto.astro`   |
| `svc-lift.webp`      | подвеска и тормоза           | `ServicePhoto.astro`   |
| `svc-electrics.webp` | электрика и ошибки           | `ServicePhoto.astro`   |
| `svc-tires.webp`     | шиномонтаж                   | `ServicePhoto.astro`   |
| `svc-polisher.webp`  | детейлинг кузова             | `ServicePhoto.astro`   |
| `svc-extractor.webp` | химчистка салона             | `ServicePhoto.astro`   |
| `svc-ceramic.webp`   | керамика и защита            | `ServicePhoto.astro`   |
| `loc-exterior.webp`  | блок «вживую», поз. 08       | `LocationPhoto.astro`  |
| `eq-tools.webp`      | баннер оборудования, поз. 09 | `EquipmentPhoto.astro` |

Мотив на карточку — свой. Раньше четыре кадра делились на восемь карточек, и в одном
ряду сетки оказывались две-три одинаковые картинки: сайт читался как шаблон.

Все кадры обезличены: без людей, брендов, вывесок, читаемого текста и госномеров —
этого требует раздел 6 спецификации, и это же снимает риск по разделу 7.

**Замена под клиента:** положите фото из шот-листа в `src/assets/photos` под теми же
именами — разметку трогать не нужно. Исходники держите в WebP (качество 85–90):
если положить PNG, Astro сгенерирует PNG-фолбэк на несколько мегабайт и бюджет
страницы улетит. Поправьте `alt` в соответствующем компоненте.

Отзывы — намеренное исключение: генерировать «скриншоты 2ГИС» нельзя, фейковые
отзывы прямо перечислены в спецификации как триггер риска. Там стоят помеченные
демо-цитаты, которые заменяются реальными скринами из карточки организации.

## Что уже сделано за вас

- **Формы без backend.** POST-запросов нет вообще: submit собирает текст и открывает `wa.me`.
  Данные не хранятся на стороне сайта — это отдельно проговорено в согласии на ПДн.
- **Юридические оговорки.** Под каждым местом со стоимостью — оговорка об информационном
  характере; под кнопками — согласие на обработку ПДн, и оба документа открываются
  ссылкой прямо из текста согласия, а не только из футера; в футере — «не является
  публичной офертой».
- **Формулировки.** На странице нет «быстро», «честно», «лучшие цены», «100% без доплат» —
  каждая выгода привязана к сроку, вилке цены или конкретному документу.
- **schema.org:** `AutoRepair` + `AutomotiveBusiness`, `OfferCatalog` из `Service`, `FAQPage`.
- **Цели Метрики.** Размечена каждая точка конверсии, а не часть: `hero_whatsapp_click`,
  `service_whatsapp_click`, `quiz_start` / `quiz_complete` / `quiz_whatsapp_click`,
  `calc_start` / `calc_complete`, `process_whatsapp_click`, `pricing_whatsapp_click`,
  `guarantee_whatsapp_click`, `faq_whatsapp_click`, `final_whatsapp_click`,
  `footer_whatsapp_click`, `mobile_whatsapp_click`, `map_open`, `phone_click`.
  Разметка декларативная — атрибут `data-goal` на ссылке, слушатель один на документ.
  Вызовы — no-op, пока `metrikaId` пуст.
- **Доступность:** навигация с клавиатуры, `aria-live` у квиза и калькулятора, тап-таргеты
  от 44px, контраст AA, полноценные состояния без hover.
- **`prefers-reduced-motion`:** Lenis не поднимается, скролл-анимации выключены, остаётся
  только смена прозрачности без смещения по оси.

## Motion

Сигнатурный момент — сборка заказ-наряда: лист выдвигается из-за кромки, по нему проходит
линия-сканер, строки проявляются по очереди, кнопка «закрепляет» лист.

Триггеры реализованы на `IntersectionObserver`, а не на GSAP ScrollTrigger: IO
отрабатывает попадание блока во вьюпорт независимо от того, чем оно вызвано — обычным
скроллом, переходом по якорю или восстановлением позиции при возврате на страницу.
Сами анимации — GSAP-таймлайны и CSS-трансформы, плавный скролл — Lenis.
На iOS Lenis не поднимается: там `sticky` + программный скролл — самое вероятное
место поломки, поэтому остаётся нативный скролл.

## Деплой

`.github/workflows/deploy.yml` собирает и публикует сайт при каждом push в `main`.

Разовая настройка в репозитории: **Settings → Pages → Source: GitHub Actions**.

`site` и `base` приходят из `actions/configure-pages`, поэтому при переезде на домен
клиента код менять не нужно — достаточно настроек Pages. Локально те же значения можно
переопределить переменными окружения:

```bash
SITE=https://example.ru BASE=/ npm run build
```

## Бюджет производительности

Цели из спецификации и факт по сборке:

| Метрика           | Цель        | Факт                                          |
| ----------------- | ----------- | --------------------------------------------- |
| JS после гидрации | ≤ 180 KB gz | ~49 KB gz (motion ~34, острова ~16)           |
| HTML              | —           | ~28 KB gz                                     |
| CSS               | —           | ~8 KB gz                                      |
| Шрифты            | —           | ~181 KB (6 подмножеств: кириллица + латиница) |
| Изображения       | —           | ~30–120 KB (AVIF, размер по вьюпорту)         |
| Вес страницы      | ≤ 1.7 MB    | ~300–400 KB                                   |

Шрифты self-host, подключены только нужные подмножества (`public/fonts`), `@font-face`
инлайном в `<head>`. Preload только у Display (Unbounded) и Body (Onest);
Data (JetBrains Mono) грузится по факту появления цифр.
