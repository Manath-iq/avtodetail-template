# Спецификация лендинга для автосервиса / детейлинга

## 0. Как пользоваться документом

У этого шаблона три слоя.
**Core** — структура, анимация, механики, юридические блоки, сетка, тон и логика CTA. Это не трогаешь между клиентами.
**Client config** — город, телефон, адрес, услуги, цены, отзывы, фото, часы работы, гарантия, ссылки, оферта. Всё это лежит в одном конфиге и в отдельных data-файлах.
**Customisation** — один H1 из трёх, палитра в пределах токенов, набор карточек услуг, коэффициенты калькулятора, тексты FAQ, порядок блоков доверия.

Цель: после замены конфига лендинг должен собираться под нового клиента за **20 минут** без ручной правки кода в компонентах.

Ниша состоит из трёх основных потоков. Доли ниже — **placeholder**, если у клиента нет своей аналитики; в проде их заменяешь фактом из Метрики/CRM.

| ------------------------------------------- | -------------: | ----------------------------------------------------------------------------- |

([Forbes.ru][2])

## 2. Позиционирование

Одна мысль, которую продаёт шаблон: **не “ремонтируем машины”, а “показываем план работ, срок и вилку цены до записи”**. Для собственника это читается как меньше споров, выше доверие, больше заявок с нормальным ожиданием.

Текст для холодного сообщения владельцу:

> У вас на сайте можно показать не просто услуги, а понятный заказ-наряд ещё до звонка: что делаем, сколько это займёт и сколько примерно стоит. Такой лендинг снимает главный страх клиента — “мне потом накрутят лишнее” — и переводит заявку в WhatsApp уже с понятным запросом.

## 3. Дизайн-концепция

### 3.1. Концепт и что он отвергает

Сейчас ниша в онлайне обычно выглядит одинаково: тёмно-серые или красно-оранжевые сайты с машиной на подъёмнике, ключами, гайками, кислотными кнопками, стоковыми фото ремзоны и словами вроде «честно», «быстро», «качественно» без доказательств. Мы делаем наоборот: **премиально, спокойно, как рабочий документ, а не как “автосервисный шаблон”**.

Концепт строится из реального артефакта ниши — **заказ-наряда / акта приёма-передачи / диагностического листа**. В новых правилах для техобслуживания и ремонта авто ключевыми остаются письменный договор/заказ-наряд, фиксация перечня работ, цены, гарантий и статуса авто; это и есть визуальная логика страницы: не “красивый гараж”, а **лист согласования, который оживает на экране**. ([Government Publication][3])

### 3.2. Токены

* `#111418` — графитовый. Фон крупных секций, когда нужен “цех”.
* `#1F2933` — угольный. Текст, бордеры, карточки с плотной типографикой.
* `#8B5E3C` — тёплый металл. Акцент на ремзону, “профессиональность”, не на скидки.
* `#D94A3A` — тормозной красный. Только для CTA, предупреждений и “срочно”.
* `#F2C14E` — сервисный жёлтый. Метки, бейджи, подсветка суммы/срока.
* `#4DA3A6` — техничный холодный. Диагностика, калибровка, “точные” элементы.
* `#F7F4EF` — бумага. Основной светлый фон блоков с текстом и карточками.

Правило: в одном экране максимум **1 яркий акцент**; всё остальное — бумага, металл и графит.

### 3.3. Типографика

* **Display:** `Unbounded` — заголовки, цифры, акцентные строки.
* **Body:** `Onest` — основной текст, FAQ, описания блоков.
* **Data:** `JetBrains Mono` — цены, сроки, коды, коэффициенты, номера заказов.

Типовой scale:

```css
--fs-hero: clamp(2.5rem, 5vw, 5.75rem);
--fs-h1: clamp(2rem, 3.8vw, 4rem);
--fs-h2: clamp(1.5rem, 2.6vw, 2.5rem);
--fs-h3: clamp(1.15rem, 1.8vw, 1.6rem);
--fs-body: clamp(1rem, 0.6vw + 0.9rem, 1.125rem);
--fs-data: clamp(0.9rem, 0.35vw + 0.8rem, 1rem);
```

Повторяющийся приём: **табличная подача с “линией заказа”** — маленькие моноширинные метки, тонкие разделители, правый столбец для суммы/срока.

### 3.4. Сетка, радиусы, разделители

* Desktop: 12 колонок, max-width 1280–1360.
* Tablet: 8 колонок.
* Mobile: 4 колонки.
* Радиусы: 28px у карточек, 20px у кнопок, 12px у чипов.
* Разделители: не линии “как в газете”, а **линии как на бланке**: пунктир, тонкая сетка, микро-подписи, перфорация.
* Отступы: больше воздуха между смысловыми блоками; внутри карточек плотная, рабочая структура.

### 3.5. Motion

Сигнатурный момент: **заказ-наряд собирается на глазах**. На скролле слева появляется “лист приёма”, по нему проходит тонкая линия-сканер, и в строках по очереди проявляются: тип работ, сроки, цена, гарантия, CTA. На последнем шаге лист “закрепляется” кнопкой `Записаться в WhatsApp`. Технически это делается через `GSAP + ScrollTrigger + CSS transforms`, без 3D и без WebGL.

Микроинтеракции:

* hover у карточек — лёгкий подъём на 2–4px, без bounce;
* выбор в квизе — немедленная подсветка, без кнопки “Далее”;
* калькулятор — мгновенный пересчёт суммы и срока;
* кнопка WhatsApp — меняет текст на “Открыть расчёт”.

Запрещённая анимация:

* бесконечно едущие машины;
* вращающиеся колёса ради красоты;
* агрессивный параллакс на каждом блоке;
* spring-bounce у всех кнопок;
* автоплей видео в hero;
* конфетти, искры, “гонка” и любые игровые эффекты;
* 3D/WebGL без реальной необходимости.

`prefers-reduced-motion`: отключаешь скролл-анимацию, оставляешь только прозрачность/смену состояния, без смещения по оси.

## 4. Структура: блоки, тексты, фото

### 1) Шапка

**Задача:** быстро дать контакт и доверие.
**Лейаут:** логотип слева, 4 якоря, справа телефон и WhatsApp.
**Копирайт:**

> Услуги
> Цены
> Квиз
> Контакты
> `Записаться`
> **Ассеты:** иконка-логотип, телефон, часы работы.
> **Анимация:** sticky, при скролле становится компактнее.
> **CTA:** WhatsApp.

### 2) Первый экран

**Задача:** объяснить, что здесь не “сайт с машинами”, а “план работ и цена до записи”.
**H1 variants, берутся из конфига:**

1. `Автосервис и детейлинг, где сначала показывают план работ, а потом берут машину`
2. `Покажем сроки, цену и список работ до записи`
3. `Ремонт и детейлинг без сюрпризов: всё фиксируется до старта`

**Копирайт:**

> Диагностика, ремонт и детейлинг с понятной сметой, сроком и согласованием допработ.
> `Получить расчёт` `Написать в WhatsApp`

**Ассеты:** крупный фрагмент заказ-наряда, не машина в кадре.
**Анимация:** лист слегка выдвигается из-за кромки, цифры считываются первыми.
**CTA:** квиз или WhatsApp.

### 3) Полоса доверия

**Задача:** снять тревогу.
**Копирайт:**

> `{ЛЕТ}` лет работы • `{ПОСТОВ}` постов • `{МАСТЕРОВ}` мастеров • `{ГАРАНТИЯ_ДНЕЙ}` дней гарантии • `{ОТЗЫВОВ}` отзывов
> **Ассеты:** 5 микро-иконок, не бейджи “лучшие”.
> **Анимация:** счётчики на скролле.
> **CTA:** к услугам.

### 4) Категории услуг

**Задача:** показать ширину работ.
**Копирайт карточек:**

> Диагностика
> ТО и расходники
> Подвеска и тормоза
> Электрика и ошибки
> Шиномонтаж
> Детейлинг кузова
> Химчистка салона
> Керамика и защита

**Ассеты:** 1 фото на 2 карточки: подъёмник, сканер, полировальная машинка, экстрактор.
**Анимация:** карточки раскрываются как вкладки в заказ-наряде.
**CTA:** `Подобрать услугу`.

### 5) Квиз-подбор

**Задача:** вывести пользователя к конкретному плану.
**Лейаут:** 4 вопроса на одном экране, тап-only, без кнопки “Next”.
**Копирайт:**

> Ответьте на 4 вопроса — и получите готовый план работ, срок и вилку цены.

**Ассеты:** тонкая схема авто сбоку.
**Анимация:** ответы подсвечиваются немедленно.
**CTA:** результат через WhatsApp.

### 6) Калькулятор

**Задача:** дать личную сумму.
**Лейаут:** слева параметры, справа сумма и срок.
**Копирайт:**

> Рассчитайте ориентир стоимости за 20 секунд.
> Итог обновляется сразу после каждого выбора.

**Ассеты:** иконки размера авто, состояния и набора работ.
**Анимация:** сумма пересчитывается без перезагрузки.
**CTA:** `Получить расчёт в WhatsApp`.

### 7) Как проходит работа

**Задача:** снять страх хаоса.
**Копирайт:**

> 1. Принимаем авто и фиксируем состояние
> 2. Согласуем план работ и допработы
> 3. Выполняем работы по заказ-наряду

## 5. Интерактивные механики

### 5.1. Квиз-подбор

**Цель:** за 4 тапа вывести человека в конкретный набор работ и готовый текст для WhatsApp.

#### Вопросы и варианты

**Q1. Что нужно?**

* `Диагностика / поиск причины`
* `Ремонт`
* `Шиномонтаж / сезонка`
* `Детейлинг / уход`

**Q2. Что по авто?**

* `Легковой седан`
* `Кроссовер / SUV`
* `Минивэн / большой кузов`
* `Не знаю`

**Q3. Когда нужно?**

* `Сегодня`
* `В ближайшие 2–3 дня`
* `На этой неделе`
* `Пока изучаю`

**Q4. Что важнее?**

* `Цена`
* `Срок`
* `Качество / гарантия`
* `Хочу максимум результата`

#### Decision matrix

Считаешь 4 score-стека: `repair`, `detail`, `seasonal`, `diagnostic`.

Правила:

* Q1 сразу даёт +4 к своему стеку.
* Q2:

  * `Не знаю` → `diagnostic +3`
  * большой кузов → `detail +1`, `seasonal +1`
* Q3:

  * `Сегодня` → `repair +2`, `seasonal +2`
* Q4:

  * `Цена` → `repair +1`, `seasonal +1`
  * `Качество / гарантия` → `detail +2`, `repair +1`
  * `Хочу максимум результата` → `detail +3`

**Итог:** берёшь максимальный стек. Если равенство — приоритет `diagnostic > repair > detail > seasonal`, потому что человеку проще согласовать точку входа через диагностику.

#### Result screen mockup

```text
┌──────────────────────────────────────┐
│ Ваш результат                        │
│                                      │
│ План: Диагностика + ремонт подвески  │
│ Срок: 2–3 часа                       │
│ Ориентир цены: 4 900–6 800 ₽         │
│                                      │
│ Что входит:                          │
│ • первичная диагностика              │
│ • проверка ходовой                   │
│ • согласование допработ              │
│                                      │
│ [Открыть WhatsApp]                   │
└──────────────────────────────────────┘
```

#### WhatsApp message format

```text
Здравствуйте! На сайте выбрал:
— {QUIZ_RESULT_NAME}
— Срок: {QUIZ_RESULT_TIME}
— Ориентир: {QUIZ_RESULT_PRICE}
— Авто: {CAR_TYPE}
— Готов записаться на {DATE_HINT}
```

#### Где живут правила

* `src/config/quiz.ts` — вопросы, варианты, веса, тексты результатов.
* `src/lib/quiz-engine.ts` — расчёт score, выбор результата, fallback.
* `src/config/client.ts` — тексты CTA и телефоны.
* `src/lib/wa.ts` — генерация `wa.me`.

### 5.2. Калькулятор

**Цель:** дать один личный, запоминающийся номер.

#### Параметры

1. `Услуга`

   * Диагностика
   * ТО
   * Ремонт
   * Детейлинг

2. `Тип кузова`

   * Седан `1.00`
   * Кроссовер `1.15`
   * SUV `1.25`
   * Минивэн `1.35`

3. `Состояние`

   * Лёгкое `1.00`
   * Среднее `1.20`
   * Сложное `1.45`

4. `Дополнения`

   * Срочный приём `+{ADDON_URGENT}`
   * Выездная подача/забор `+{ADDON_PICKUP}`
   * Дополнительная химия/материалы `+{ADDON_MATERIALS}`

#### Формула

```text
final_price =
base_service_price
× body_coef
× condition_coef
+ addon_sum
```

**Пример логики для срока:**

* базовый срок услуги = `{BASE_HOURS}`
* `Сложное` состояние → `+30%`
* `Срочный приём` → `-20%` к ожиданию в очереди, но `+{ADDON_URGENT}` к цене

**Данные редактируются в конфиге, а не в компоненте.**

## 6. Контент

### Шот-лист для реального клиента

1. Фасад и вход.
2. Парковка и как подъехать.
3. Ресепшен / зона приёма.

8. Пост мойки / химчистки / детейлинга.
9. Полировальная машинка в работе.
10. Заказ-наряд / бланк приёма.
11. Фото “до / после”.
12. Место ожидания клиента.
13. Реальный прайс или лист услуг.
14. Команда без постановочной улыбки.
15. Карта проезда с привязкой к входу.

Требования к исходникам:

* минимум 3000 px по длинной стороне;
* горизонтальные кадры 3:2 и 4:3;
* без фильтров и “дорогих” пересветов;
* без логотипов поставщиков, масел, шин и химии, если клиент не хочет публично светить бренды;
* без скриншотов из мессенджеров и без липовых “до/после”.

### Что использовать в демо вместо реальных фото

* нейтральный бокс;
* чистый лист заказ-наряда;
* крупные планы инструмента;
* обезличенные машины без номеров;
* общие кадры ремзоны и детейлинга без брендов.

### AI-подсказки для демо-ассетов

1. `Фотографический кадр автосервиса: чистая ремзона, подъёмник, диагностический сканер на тележке, мягкий естественный свет, без людей, без брендов, без текста, без номеров, реалистично, premium but practical`
2. `Крупный план заказ-наряда на металлическом столе в сервисе, рядом ручка, штамп, линейка, тонкая бумажная сетка, чистая композиция, без логотипов, без читаемого текста`
3. `Детейлинг-студия: полировальная машинка, экстрактор, микрофибра, лампа контроля ЛКП, аккуратная рабочая поверхность, без людей, без брендов, без текста`

### Три правила тона

* Не обещай “честно” и “лучше всех” без цифр или бланка.
* Не пиши как технарь для технарей; человек должен понять выгоду за 5 секунд.
* В каждой выгоде должен быть либо срок, либо вилка цены, либо конкретный результат.

## 7. Юридические требования

Для этой ниши шаблон должен опираться на три вещи: **правдивость рекламы**, **отдельное согласие на ПДн** и **понятные правила оказания услуг по ремонту/ТО**. По закону о рекламе реклама должна быть добросовестной и достоверной; по 152-ФЗ согласие на обработку персональных данных оформляется отдельно от других документов; по новым правилам для автосервиса с 1 сентября 2025 года применяются актуальные правила оказания услуг по техобслуживанию и ремонту авто. ([Government of Russia][4])

### Мандаторный текст

Под формой и в футере:

> Нажимая кнопку, вы соглашаетесь с Политикой обработки персональных данных и Согласием на обработку персональных данных.

Под ценами:

> Информация о стоимости носит информационный характер и может быть уточнена после осмотра автомобиля.

В футере:

> Информация на сайте не является публичной офертой.

### Что обязательно вывести в интерфейсе

* Политика обработки ПДн.
* Отдельное согласие на обработку ПДн.
* Контакты и режим работы.
* Юридическое лицо / ИП.
* Условия гарантии, если клиент их заявляет.
* Правила по приёму авто, если есть форма записи.

### Какие формулировки не использовать

* `100% без доплат`
* `гарантируем идеальный результат`
* `ремонт любой сложности за фикс`
* `лучшие цены`
* `самый честный сервис`

Почему: реклама должна быть достоверной, а недостоверные обещания и неподтверждённые сравнения — прямой риск по 38-ФЗ. ([Government of Russia][4])

### Триггеры модерации и риска

* скрытая цена в форме без пояснения;
* “бесплатно” без ограничений;
* фейковые отзывы и скрины;
* обещание результата без осмотра;
* автозвонки, рассылки и сообщения без согласия;
* сбор ПДн без отдельного согласия и без политики.

Для ПДн держи отдельный документ политики и не прячь его в договор; РКН отдельно публикует требования к политике и уведомлению оператора о начале обработки ПДн. ([RKN][5])

### Документы, которые должны существовать у клиента

* заказ-наряд;
* акт приёма-передачи / осмотра;
* политика обработки ПДн;
* согласие на ПДн;
* условия гарантии;
* прайс или перечень услуг;
* реквизиты исполнителя.

Нюанс по шаблону: блок лицензий не делай базовым, если клиент сам не заявляет отдельную регулируемую деятельность; здесь важнее порядок документов по ремонту, ПДн и рекламе. Это следует из найденных правил для автосервиса и требований к сайту, а не из “красоты” страницы. ([Government Publication][3])

## 8. Технические требования

**Stack:** Astro + Tailwind + TS, GSAP + ScrollTrigger, Lenis. Жёсткая островная гидрация только там, где есть квиз, калькулятор, карта и sticky-лента.

### Бюджет

| Метрика                  |        Цель |
| ------------------------ | ----------: |
| LCP                      |     ≤ 2.2 s |
| CLS                      |      ≤ 0.05 |
| Total page weight        |    ≤ 1.7 MB |
| JS after hydration       | ≤ 180 KB gz |
| Lighthouse Performance   |        ≥ 90 |
| Lighthouse Accessibility |        ≥ 95 |

### Медиа

* hero-картинка: AVIF + WebP fallback;
* все второстепенные фото: lazy-load;
* видео не встраивать в hero;
* демо-ассеты хранить отдельно от клиентских.

### Шрифты

* self-host;
* preload только `Display` и `Body`;
* `Data` грузить по факту появления калькулятора.

### SEO

* `AutoRepair` для автосервисной части,
* `AutomotiveBusiness` как более общий слой,
* `Service` для описания услуг,
* `FAQPage` для блока FAQ. Эти типы существуют в schema.org и подходят под страницу услуг автосервиса/ремонта. ([Schema.org][6])

### Формы без backend

* форма не отправляет POST;
* submit открывает `wa.me` с уже собранным текстом;
* в UI сразу показывай короткое подтверждение: `Расчёт открыт в WhatsApp`;
* не хранить данные на сервере демо-страницы.

### Яндекс.Метрика

Голы:

* `hero_whatsapp_click`
* `quiz_start`
* `quiz_complete`
* `calc_complete`
* `map_open`
* `footer_whatsapp_click`

### Доступность

* вся навигация с клавиатуры;
* у квиза и калькулятора есть `aria-live`;
* контраст текста не ниже AA;
* тап-таргеты от 44px;
* no-hover state должен быть полноценным, не “обрезком”.

### Браузерная матрица

* iOS Safari — приоритет.
* Chrome Android — приоритет.
* Desktop Safari / Chrome / Firefox — поддержка.
* Самое вероятное место поломки: `100svh` + sticky секции + scroll-lock на iOS. Закладывай fallback на `min-height` и отдельный safe-area padding.

## 9. Конфиг подмены под клиента

Храни всё в одном месте: `src/config/client.ts`, `src/config/services.ts`, `src/config/pricing.ts`, `src/content/reviews.ts`, `src/content/faq.ts`.

export type ClientConfig = {

  city: string;
  region: string;
  address: string;
  phone: string;

  heroH1Options: [string, string, string];
  heroSubhead: string;
  heroCtas: {
    primary: string;
    secondary: string;
  };

  proof: {
    years: string;
    posts: string;

  };

  services: Array<{
    id: string;
